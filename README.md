# Учебный бот (этап 1)

Личный Telegram-бот для учёбы: предметы, конспекты (фото, PDF, файлы, текст), архив по датам,
поиск, теги и «важно к экзамену», PDF из текста, выгрузка предмета одним PDF, карточки
преподавателей. Отвечает только тебе.

**Хостинг: Render (бесплатный тариф, без банковской карты) + UptimeRobot (бесплатно).**

---------------------------------------------------------------------

## Как это устроено (коротко и честно)

- Бесплатный сервис Render засыпает через 15 минут без обращений, а его диск стирается при
  каждом перезапуске, засыпании и обновлении.
- Поэтому: (1) бот работает через **webhook**: Telegram сам стучится в сервис, и это будит его;
  (2) бесплатный **UptimeRobot** обращается к сервису раз в 5 минут, так что он почти не спит;
  (3) база **копируется тебе в Telegram** через ~30 секунд после любого изменения, а при старте
  бот сам восстанавливает её из закреплённого сообщения.
- Бесплатных часов у Render 750 в месяц на аккаунт, а круглосуточная работа одного сервиса это
  744 часа в самом длинном месяце. Значит, хватает **только на один сервис**.
- Если изменение сделано меньше чем за ~30 секунд до сбоя, оно может потеряться.
- Если пингер не работает и сервис уснул, первое сообщение боту ответит примерно через минуту.
- Условия бесплатных тарифов могут измениться. Если Render вдруг попросит банковскую карту,
  остановись и напиши мне.

## 1. Токен и твой ID

1. В Telegram найди **@BotFather**, отправь `/newbot`, придумай имя и логин (кончается на `bot`).
   Он пришлёт **токен**, длинную строку с двоеточием. Никому его не показывай.
2. Найди **@userinfobot**, отправь любое сообщение. Он ответит числом, это твой **ID**.
3. Открой своего бота и нажми **Start**. Это обязательно: иначе бот не сможет писать тебе бэкапы.

## 2. GitHub (хранит код, карта не нужна)

1. Зарегистрируйся на https://github.com (бесплатно).
2. Нажми **+** → **New repository**. Имя: `study-bot`. Выбери **Public** (в коде нет секретов:
   токен вводится отдельно в Render). Нажми **Create repository**.
3. На странице репозитория нажми ссылку **uploading an existing file**.
4. Распакуй `study-bot.zip` на компьютере и **перетащи в окно браузера всё содержимое папки**
   `study-bot` (папки `bot` и `fonts` и все файлы). Скрытые файлы (`.gitignore`, `.dockerignore`,
   `.env.example`) тоже нужны: в Windows включи показ скрытых файлов.
5. Внизу нажми **Commit changes**. Убедись, что в репозитории видны `Dockerfile`, `bot/`,
   `fonts/`, `requirements.txt`.

## 3. Render (сам сервер)

1. Зайди на https://render.com → **Get Started** → войди через GitHub.
2. **New +** → **Web Service** → выбери репозиторий `study-bot` (при первом разе нажми
   «Configure account» и дай Render доступ к репозиторию).
3. Настройки:
   - **Language / Runtime**: **Docker**
   - **Instance Type**: **Free**
   - **Environment Variables** → добавь:
     - `BOT_TOKEN` = твой токен
     - `OWNER_ID` = твой ID (только цифры)
     - `TIMEZONE` = `Europe/Warsaw` (твой пояс; необязательно)
4. Нажми **Create Web Service**. Сборка занимает несколько минут. В логах должна появиться
   строка **«Бот запущен (webhook)»**.
5. Вверху страницы сервиса виден адрес вида `https://study-bot-xxxx.onrender.com`. Скопируй.
6. Отправь боту `/start`. Должно появиться меню.

Если бот молчит, а в логах нет ошибок: добавь переменную `WEBHOOK_BASE_URL` с адресом сервиса
(без слэша в конце) и нажми **Manual Deploy → Deploy latest commit**.

## 4. UptimeRobot (чтобы сервис не засыпал)

1. Зарегистрируйся на https://uptimerobot.com (Free, карта не нужна).
2. **Add New Monitor** → тип **HTTP(s)** → URL: `https://study-bot-xxxx.onrender.com/health`
   (твой адрес + `/health`) → интервал **5 minutes** → **Create**.
3. Монитор должен показать **Up**.

## 5. Проверка

1. Через 20-30 минут напиши боту: ответ должен прийти сразу (значит, сервис не спит).
2. Добавь предмет и один материал. Через минуту в чате с ботом появится сообщение
   «💾 Бэкап базы» (закреплённое). Дальше оно просто обновляется, новые не плодятся.
3. **Проверка восстановления:** в Render → **Manual Deploy → Deploy latest commit**. Это стирает
   диск. После запуска бот напишет «♻️ Сервер перезапускался. Я восстановил базу», а все
   предметы и материалы будут на месте.

## 6. Как обновлять код

Загрузи изменённые файлы в GitHub (Add file → Upload files). Render пересоберёт сервис сам.

## 7. Бэкап

- Не удаляй закреплённое сообщение с бэкапом и не закрепляй в чате с ботом другие сообщения.
- Кнопка «💾 Бэкап» делает бэкап немедленно.
- Пустую базу бот не бэкапит, чтобы не затереть хороший бэкап.
- Хранятся только тексты и file_id; сами файлы лежат у Telegram. Если удалить файл из
  Telegram, в архиве он перестанет открываться.

## 8. Если что-то не работает

| Симптом | Что делать |
|---|---|
| В логах «Не задана переменная окружения» | В Render → Environment проверь `BOT_TOKEN` и `OWNER_ID` |
| Бот молчит | Нажми Start у бота; проверь `OWNER_ID`; смотри логи в Render |
| В логах `Unauthorized` | Токен неверный: возьми заново у @BotFather и поправь в Render |
| Бот отвечает с большой задержкой | Сервис уснул: проверь, что UptimeRobot показывает Up |
| «Кнопка устарела» | Был перезапуск; открой нужный раздел заново |
| Файл выгрузки больше 49 МБ | Выгружай по частям (по периоду или тегу в архиве) |
| «Не удалось получить файл» | Бот скачивает файлы из Telegram только до 20 МБ |

## 9. Запуск на своём компьютере (для проверки)

Нужен Python 3.11+.
```
python -m venv venv
venv\Scripts\activate          (Windows)      source venv/bin/activate   (Mac/Linux)
pip install -r requirements.txt
copy .env.example .env         (Windows)      cp .env.example .env       (Mac/Linux)
```
Впиши в `.env` токен и ID (строку `WEBHOOK_BASE_URL` не трогай, она закомментирована). Затем
`python -m bot.main`. Остановить: Ctrl+C.

Файл `docker-compose.yml` нужен только если когда-нибудь появится собственный сервер или VPS:
`docker compose up -d --build`.
